# 03 · 发布与同步（维护者视角）

> **读者：本模板的维护者。** 用模板开新项目的人不需要读这份——他们读
> [`01-使用指南.md`](01-使用指南.md) 就够了。
>
> 本文回答三件事：**公开仓库是什么形态 / 怎么把源头的改动同步上去 / 什么东西永远不许上去。**

---

## 1. 两个东西，别搞混

| | 本地源头 | GitHub 公开仓库 |
|---|---|---|
| 在哪 | 你机器上的 `agent-project-scaffold/` | `github.com/dusword/agent-project-scaffold` |
| 形态 | 🔴 **1 个 git 仓库，里面并排装着 7 个项目单元**（展馆模式，[`02-设计决策.md`](02-设计决策.md) D11） | 🔴 **1 个仓库，一份压平的快照** |
| 是什么 | **真相源**。所有改动在这里做 | **分发副本**。只读消费，不在上面改内容 |
| 历史 | 一份历史，**按单元各记各的日志**：动哪个单元就在那个单元的 `CHANGE-LOG.md` 净增一行 | 只有发布提交（🔴 **源头历史永不随分发**，见下） |

**单向流动：源头 → 公开仓库。** 反过来不成立——公开仓库上不许直接改内容，
否则下一次同步（rsync 覆盖）会把它无声抹掉。

### 🔴 铁律：源头的 git 历史**永不**直接 push 到公开仓库

**公开仓库永远走快照制。** 不许 `git remote add` 然后 `push`，不许 `filter-branch` 洗一遍再推，
不许用 `subtree split` 把某个单元的历史推上去。**一次都不许。**

理由是一条硬事实：

> **出口安检（§2）扫的是工作区，不扫 git 历史。**

而源头历史里**确实有**今天工作区里已经不存在的东西——脱敏之前的文本内容，
以及真实的提交身份（作者名与邮箱写在每一条 commit 对象里，`--exclude-dir=.git` 一个字都扫不到）。
换句话说：**当前工作区通过安检，不代表历史通过安检**；把历史推上去等于把所有安检结论作废。

（这条的来龙去脉见 [`02-设计决策.md`](02-设计决策.md) **L11**。
🔴 那里也**没有**写出具体是哪些值——写出来本身就是又一次泄漏，同 L5 那条教训的形状。）

**代价（接受）**：公开仓库看不到源头的开发史，「一条日志 = 一次提交」在分发副本里对不上号。
这个代价已经在 D10 / `01` §0 里对读者如实说明了，比泄漏便宜得多。

### 为什么必须压平

GitHub 上**一个仓库只能有一份 git 历史**——但那已经不是压平的主要理由了
（源头现在本来就是一个仓库）。**现在的理由是上面那条铁律：历史不出境。**
所以选压平，代价用 [`../scripts/init-repos.sh`](../scripts/init-repos.sh) 在消费端补回来（D10）。

## 2. 🔴 黑名单：这些东西永远不许进公开仓库

发布前**必须**全文扫一遍。命中任何一条就**停下来，不许硬推**。

| 类别 | 扫什么 |
|---|---|
| 令牌 / 密钥形状 | 各平台的访问令牌（GitHub / 云厂商 / 第三方接口）、PEM 私钥块 |
| 内网与服务器 | 内网 IP、公网服务器 IP、内部服务名 / systemd 单元名 |
| 个人痕迹 | 本机用户名、家目录绝对路径、个人 handle、公司名、**任何邮箱地址** |
| 绝对路径 | 任何指向某台机器上某个家目录的路径——本体系本来就禁绝对路径（[`00-架构规范.md`](00-架构规范.md) §3），发布前再确认一次 |
| 真实业务数据 | 真实商品 / 客户 / 订单 / 价格。示例内容一律中性编造 |

一条扫描命令，在源头根目录跑（逐项列出文件名与行号）：

```bash
/usr/bin/grep -rnE 'gho_|AKIA|-----BEGIN|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|/Users/|/home/' . \
  --exclude-dir=.git --exclude-dir=.migration-backup \
  --exclude-dir=__pycache__ --exclude-dir=.pytest_cache
```

### 🔴 为什么写死 `/usr/bin/grep`，而不是裸写 `grep`

（这是实测踩出来的，教训见 [`02-设计决策.md`](02-设计决策.md) **L12**。）

`grep` 只是一个**名字**，PATH 上任何东西都可以接管它——ugrep、ripgrep 的兼容壳、一层 shell 函数。
而这类替代品**默认遵守 `.gitignore`**。本仓恰好有两份 `.gitignore` 各写着一行 `projects/`
（模具自己的、`demo-parent-project` 自己的，是**出厂形态**、刻意保留、不许删，见 §3.3）——
于是安检会**一声不吭地跳过 5 个项目单元**，只扫了根单元就报「命中为零」。

> 🔴 **「零命中」在这种情况下不是安全信号，是扫描器根本没去过那里。**

写死绝对路径，扫的就一定是那个不认 `.gitignore` 的系统 grep：**扫谁由参数说了算，不由环境说了算。**
注意 `--exclude-dir=.git` 在这件事上**帮不上忙**——参数写得再对，也管不住换了一个工具。

🔴 **用前花一秒钟做正例校准**：先让扫描器去找一个**确定存在**的东西，
它数得对，它说的「没找到」才作数。

```bash
/usr/bin/grep -rl '项目' --include=CLAUDE.md . --exclude-dir=.git --exclude-dir=.migration-backup | wc -l
# 必须是 7（本仓 7 个项目单元各有一份宪法）。数出 2 就说明这个扫描器在遵守 .gitignore，
# 它这一趟给出的任何「干净」结论都不作数。对照基准：find . -name CLAUDE.md | wc -l
```

⚠️ **排除项要与 §3.1 的 rsync 排除清单保持一致。** 钉死系统 grep 之后 `.gitignore` 不再遮挡，
`.migration-backup/`（旧仓库留档，装着真实提交身份）与 `__pycache__` / `.pytest_cache`
（编译产物里嵌着本机绝对路径）会一起被扫出来，实测能把命中从 2 条顶到 **165 条**。
这三样**根本不会出境**，扫它们只制造噪音——**而噪音正是「命中即停」这条规矩被关掉的方式。**

⚠️ **可以放行的命中只有一种：文档里引用的扫描命令文本本身。** 目前有两处：

| 位置 | 命中什么 | 为什么是误报 |
|---|---|---|
| 本文上面那行 `/usr/bin/grep` | 它自己写的那几个检索模式 | 那是**要找的东西**，不是被找到的东西 |
| [`01-使用指南.md`](01-使用指南.md) §5 自检项 | 同类的一个路径模式 | 同上，那是自检清单里的命令原文 |

🔴 **别在别处再抄一遍这些模式。** 每多抄一处，安检就多一条要人工判断的误报，
而误报越多，「命中即停」这条规矩就越会被当成噪音关掉——扫描清单本身也要保持低噪。

🔴 **判为误报必须逐条写出理由**，不许笼统一句「都是误报」放过——
这正是 [`02-设计决策.md`](02-设计决策.md) L5 那个教训的形状：清单里写着「应当被拒绝」，
而没人真的看一眼它到底拒没拒。

🔴 **人名也按黑名单处理。** 正文一律称「项目主人」，不写真名——
对外部读者来说，一个没被介绍过的名字本来就读不懂，所以这既是隐私处理也是文档质量。
版权行用 GitHub 账号名（见 [`../LICENSE`](../LICENSE)）。

## 3. 同步步骤

### 3.1 首次发布（已完成，记在这里供以后重建）

```bash
# 1. 压平导出：排除 .git 与运行时垃圾，**保留 .claude/ .githooks/ 等点目录**
#    🔴 .migration-backup/ 是单仓迁移时移出来的旧嵌套 .git 留档，只在本机保存，
#       它本身就是一堆 git 历史 —— 让它出境等于绕开上面那条铁律。
rsync -a --exclude='.git' --exclude='.migration-backup' \
         --exclude='.pytest_cache' --exclude='__pycache__' \
         --exclude='cross-edit-allow' \
         <源头>/ <导出目录>/

# 2. 出口安检（见 §2），命中就停
# 3. 核对文件数与源头对得上（除排除项）
# 4. 在导出目录建仓库并提交（分几个自洽的提交，不要一坨）
cd <导出目录>
git init -b main
git config user.name  "dusword"
git config user.email "<账号名>@users.noreply.github.com"    # 🔴 GitHub 隐私邮箱，不用公司邮箱

git add CLAUDE.md .gitignore LICENSE .claude .githooks scripts   # 骨架
git commit -m "chore: 项目骨架 —— ..."
git add README.md CHANGE-LOG.md docs                             # 文档
git commit -m "docs: 四份说明书 + README 落地页"
git add -f projects                                              # 🔴 模具，-f 的理由见 §3.3
git commit -m "feat: 收录出厂纯净的模具 —— ..."

# 5. 建公开仓库并推送
gh repo create agent-project-scaffold --public --source . --push
```

### 3.2 后续同步（改了源头之后）

🔴 **先确认「导出目录」在哪。** 它只是一个中转工作区，**不是必须长期保存的东西**——
首发时它建在临时目录里，机器重启就没了。找不到它的时候不要慌，也不要重新走 §3.1，
**直接把公开仓库 clone 下来当导出目录用**（它本来就是那份快照，带着 remote 和历史）：

```bash
gh repo clone dusword/agent-project-scaffold <导出目录>
```

确认好导出目录之后：

```bash
# 1. 先在源头把改动按纪律提交完（动过哪些单元，就有哪几行日志）
#    源头是单一仓库，一条命令看全树，输出为空才算干净：
git status --porcelain

#    再按单元核对账本，每个单元两个数字必须相等（merge 提交豁免）：
#      git rev-list --no-merges --count HEAD -- <单元路径> ":(exclude)<单元路径>/projects"
#      grep -cE '^\| [0-9]{4}-' <单元路径>/CHANGE-LOG.md
#    （仓库根这个单元把路径换成 . 和 ":(exclude)projects"）

# 2. rsync 覆盖进已有的导出目录（同 §3.1 第 1 步，排除项一字不改）
#    ⚠️ 不要加 --delete 之前先想清楚：导出目录里有它自己的 .git，
#       --delete 配上错误的 --exclude 会把它删掉。要用就必须保留 --exclude='.git'。

# 3. 出口安检（§2）

# 4. 看清 rsync 改到了什么，再按显式路径暂存
cd <导出目录>
git status --short                      # ← 先看，别闭眼提交
git add <上面列出来的路径>              # projects/ 下的路径要加 -f，理由见 §3.3
git commit -m "docs: 同步源头改动 —— <一句话>"
git push
```

🔴 **这里也不用 `git add -A`。** 本体系的提交纪律是「一律显式路径」
（[`00-架构规范.md`](00-架构规范.md) §4），发布仓库虽然不受提交硬闸约束，
但**没有理由在自己的发布流程里演示一个自己禁止的动作**——公开仓库是教材，
读者会照着学。而且 `-A` 在这里有实际风险：rsync 之后工作区里可能有你没预期的删除，
闭眼 `-A` 会把它们一起提上去。**唯一的例外是 [`../scripts/init-repos.sh`](../scripts/init-repos.sh)
里的首次提交**，它的注释写明了为什么那一处说得通。

### 3.3 🔴 为什么发布提交要 `git add -f projects/`

🔴 **口径随 D11 变了一半，但结论没变：这里仍然必须加 `-f`。**

源头**根**的 `.gitignore` 已经不再排除 `projects/`（本仓是单一仓库，模具是被跟踪的展品）。
但**模具与 `demo-parent-project` 自己的 `.gitignore` 里仍然写着 `projects/`**——
那是它们的出厂形态（它们要教给真实项目的正是「父仓库排除 `projects/`」，D1），刻意保留。

导出目录是 rsync 的**逐字副本**，那两份 `.gitignore` 也一模一样。所以在导出目录里：

| | 不加 `-f` 会怎样 |
|---|---|
| 模具本身（`projects/main-sub-architecture-project-demo/` 那一层的文件） | ✅ 正常提交 |
| 模具下面的四个 demo + 那个孙项目 | ❌ **被静默忽略**，公开仓库里只剩一个空壳模具 |

为什么不干脆把导出目录的 `.gitignore` 改掉：

| 方案 | 否掉的理由 |
|---|---|
| 导出时删掉模具 `.gitignore` 里的 `projects/` | 制造了源头与导出的**内容差异**，每次 rsync 同步都会被覆盖回去、每次都要重做一遍。而且这条 `.gitignore` 本身是教材（读者会照着学），改坏了会教错人 |
| 把 demo 挪到一个不被 ignore 的目录名（如 `template/`） | 公开仓库的结构就和规范 §1 画的树不一样了。模板的第一课是目录约定，**不能为了发布把这一课改掉** |

`git add -f` 只在**发布提交**这一处使用。
🔴 **源头也会撞上同一件事**：在本仓往模具的 `projects/` 下**新增**文件同样需要 `git add -f`，
漏网检查命令见 [`../README.md`](../README.md)「关于 `projects/` 的两件事」，教训见
[`02-设计决策.md`](02-设计决策.md) **L10**。

### 3.4 关于发布提交与本地纪律的关系

导出目录里**也有 `.githooks/pre-commit` 这个文件**（它是模板内容的一部分），
但导出目录**没有执行 `git config core.hooksPath .githooks`**，所以那个钩子不生效——
**发布提交不受「改动必留日志」硬闸约束**。这是有意的：一次发布提交对应源头的多次改动，
硬套「一条记录 = 一次提交」没有意义。

🔴 **但 `CHANGE-LOG.md` 里必须有对应的发布记录行**，理由是自洽：
公开仓库里躺着一份声称「任何改动都要留一行日志」的 `CHANGE-LOG.md`，
而这次发布本身不在里面，读的人第一眼就会发现体系在自己身上没执行。
所以顺序是：**先在源头记一条「发布 / 同步到公开仓库」并提交，再 rsync 导出**——
这样那条记录随文件一起过去了。

## 4. 发布后的验证清单

推送完逐条核对，**不许只看 `gh repo create` 没报错就算完**：

- [ ] `gh api repos/dusword/agent-project-scaffold --jq '.visibility, .default_branch'` → `public` / `main`
- [ ] `gh repo clone dusword/agent-project-scaffold <临时目录>` 能 clone 下来
- [ ] 临时目录里文件数与源头对得上（除排除项）
- [ ] 在临时目录跑 `bash scripts/init-repos.sh` → **还原 1 个仓库（就是根）**、退出码 0，
      并且**没有**打印「树里有嵌套 `.git`」的警告（打印了说明导出目录不干净，`.git` 被 rsync 带过去了）
- [ ] 抽一个项目单元验硬闸真的生效（v2 按单元判定）：只改某个单元的文件、不补**它自己的**日志，
      **应当被拒绝**，且报错点名的是那个单元而不是仓库根
  ```bash
  cd <临时目录>/projects/main-sub-architecture-project-demo
  echo x >> README.md && git add README.md && git commit -m test    # 期望：被拒
  # 期望报错里写着：单元【projects/main-sub-architecture-project-demo】缺日志
  ```
- [ ] README 首屏内容完整（读回文件确认，不靠浏览器目测）
- [ ] 公开仓库里搜一遍黑名单（§2 那条 `/usr/bin/grep` 在 clone 下来的副本上再跑一次，
      🔴 **同样先做正例校准**——clone 下来的副本里那两份 `.gitignore` 原样还在，
      裸写 `grep` 会在这里再漏扫一次）

## 5. 已知不做的事

| 项 | 状态 |
|---|---|
| 自动化同步脚本（`publish.sh`） | **不写**。同 [`02-设计决策.md`](02-设计决策.md) D7 的判据：同步一次就那 4 条命令，且出口安检**必须由人看一眼**，包成脚本反而会让人跳过看的那一步 |
| GitHub Actions / CI | 不做。本仓库没有可测的代码产物，钩子的自测命令在 [`00-架构规范.md`](00-架构规范.md) §9，手工跑 |
| 版本号 / release / tag | 暂不做。模板还在演化，打版本号会给人「这版稳定了」的错觉 |
| 把源头的 git 历史也发上去（push / `filter-branch` 洗一遍再推 / `subtree split` 推某个单元） | 🔴 **明令禁止，见 §1 那条铁律。** 不是「做不到」而是「不许做」：出口安检只扫工作区、不扫历史，而历史里有脱敏之前的内容和真实的提交身份。公开仓库**永远走快照制**（来龙去脉见 [`02-设计决策.md`](02-设计决策.md) L11） |
