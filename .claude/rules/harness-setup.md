# 确立仪式 · harness 怎么算「针对本项目立过了」

> 触发器是 `.claude/hooks/harness-check.sh`（SessionStart）。
> 本文件是仪式的**操作手册**：agent 被触发后照这个做。

---

## 1. 什么是 harness

harness =「这个项目的规矩装置」，四样东西合起来：

| 件 | 位置 | 作用 |
|---|---|---|
| 宪法 | `CLAUDE.md`（**项目根**） | 这个项目怎么干活（范式、纪律、边界） |
| 规矩 | `.claude/rules/*.md` | 逐条可执行的细则 |
| 钩子 | `.claude/hooks/` + `.githooks/` | 把关键几条变成机器强制 |
| 状态 | `.claude/HARNESS-STATUS.md` | 记录「这套装置针对本项目确立过了」 |

前三样是**从模板复制来的**，所以一定是通用的、不贴合具体项目的。
确立仪式就是把它**贴合到本项目**的那一次对话。

---

## 2. 🔴 为什么复制改名后会自动重新触发

`harness-check.sh` 判定「未确立」的三个条件：

1. `.claude/HARNESS-STATUS.md` 不存在
2. 状态行写着「`## 当前状态：未确立`」（🔴 行首锚定的完整前缀，不是在全文里找「未确立」三个字）
3. **文件里 `- 项目名：` 记录的名字 ≠ 当前目录名**

第 3 条是整套机制的**机关**：

```
demo-code-project/            HARNESS-STATUS 记录「demo-code-project」→ 名字对上 → 安静
        ↓ 复制 + 改名
my-new-tool/                  HARNESS-STATUS 仍记录「demo-code-project」→ 对不上 → 触发仪式
```

**好处**：不需要写重置脚本，不需要人记得去清状态，**忘不掉**。
复制改名这个动作本身就把状态弄「脏」了，而脏状态正是我们要的信号。

**副作用（要知道）**：给项目目录改名 = 重新触发一次仪式。
这是可接受的——目录改名通常意味着定位变了，重新对一次规矩本来就该做。
如果确实只是改个名、规矩一字不动，仪式走完在「改动摘要」里写「仅目录改名，规矩沿用」即可。

## 3. 仪式四步

### ① 读背景（不问用户，自己读）

按顺序读：`README.md` → `docs/` 下所有文档 → `CLAUDE.md`（项目根）→ `.claude/rules/*.md`。

读完你应该能回答：这是什么项目、属于四类中的哪一类、它现在继承的默认规矩是什么。
**读不明白就继续读，不要带着疑问去问用户那些文档里写着的事。**

### ② 问用户 3~5 个问题（一次问完）

推荐问这几个，按项目情况裁剪：

1. 这个项目的目标是什么？**交付物是什么形态**（能跑的应用 / 一份结论 / 一批可引用的知识 / 一组子项目）？
2. 有没有本项目特有的纪律？（例：花钱前要报预算、上线前必须人工验收、某类数据不许外传）
3. 继承来的默认规矩里，哪条要改、哪条要删？
4. 有没有要提前说清的边界？（不许碰什么、做什么之前必须先问）
5. 这个项目会不会再往下嵌子项目？

🔴 **一次问完，不要挤牙膏。** 用户回答完就直接进第 ③ 步，不要追加第二轮提问。

### ③ 按需改宪法

把第 ② 步的回答落到 `CLAUDE.md`（项目根，必要时也改 `.claude/rules/`）。

🔴 **允许一字不改。** 默认宪法本来就是按四类范式写好的，很多项目直接沿用就是对的。
一字不改也是一个**有效的确立结果**，不是偷懒——只要在第 ④ 步如实写明。

⚠️ 反过来：**不要为了显得做了事而瞎改宪法**。改动越多，后来的人越难判断哪些是通用规矩、哪些是本项目特例。

### ④ 写状态文件

`.claude/HARNESS-STATUS.md` 必须含这四行，格式**照抄**（钩子按 `- 项目名：` 这个前缀解析）：

```markdown
- 项目名：<必须精确等于当前目录名>
- 确立日期：<YYYY-MM-DD>
- 确认人：<用户名字>
- 改动摘要：<改了哪几条 / 或「沿用默认，未作改动」>
```

🔴 **`- 项目名：` 那一行写错，下次开会话会再触发一次仪式。** 写完自己核对一遍目录名。

---

## 4. 用户说「跳过」怎么办

照办。但要明确告诉他：

> 好，跳过。提醒一下：状态文件没更新，下次开会话还会再提示一次。
> 想彻底关掉，就把 `.claude/HARNESS-STATUS.md` 的项目名改成当前目录名。

**不要偷偷替他把状态文件改了**——那等于伪造了一次没发生过的确认。
状态文件里的「确认人」是有含义的，不能是你自己。
