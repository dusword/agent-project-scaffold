# 项目边界 · 只写自己这棵树

> 这条规矩由 `.claude/hooks/boundary-guard.sh` 机器强制（PreToolUse / Write|Edit，越界退出码 2）。
> 本文件解释**为什么**、以及**要跨界时的正规流程**。

---

## 1. 铁律

**你只许写自己这个项目树里的文件。**

「自己这个项目树」= `$CLAUDE_PROJECT_DIR` 指向的那个目录及其全部子目录。

包括但不限于这些越界动作，一律先停下来问：

| 想干的事 | 判定 |
|---|---|
| 改隔壁子项目的源码 / 文档 | 越界 |
| 改父项目的 README 或 CHANGE-LOG | 越界（父项目的日志由在父项目里工作的人写） |
| 往用户家目录写配置 / 缓存 | 越界 |
| 改本项目的 `.claude/` 与 `docs/` | ✅ 在界内，随便改 |

---

## 2. 为什么要有这条

「总项目 - 多子项目」体系里，每个项目是**独立的 git 仓库**、有自己的 CHANGE-LOG 与提交硬闸。
一个 agent 顺手改了隔壁项目，会造成三件坏事：

1. **改动无日志**——它不在隔壁的提交流程里，隔壁的 CHANGE-LOG 不会记这笔。
2. **改动无审阅**——隔壁项目的负责人下次打开时，看到一堆来路不明的 diff。
3. **上下文错位**——你读的是本项目的宪法，改的却是遵守另一套宪法的代码。

所以边界不是洁癖，是**让每个仓库的历史都能自证清白**。

---

## 3. 🔴 跨项目授权流程（四步，不许简化）

真的需要改别人的树时，走这个流程：

### 第一步：停下来，向用户说清楚

不要试探、不要「先改了再说」。原地停住，一次说清三件事：

- 我要改哪个项目的哪个文件（写全路径前缀）
- 为什么必须在这里改，而不是在那个项目里改
- 改完会产生什么后果

### 第二步：用户口头同意后，写放行条

在**本项目**根下创建 `.claude/cross-edit-allow`，每行一个被授权的路径前缀：

```
# 每行一个路径前缀；# 起头的是注释
# 允许绝对路径，也允许相对本项目根的路径
../demo-docs-project/inbox
```

放行条的两条硬性质：

| 性质 | 说明 |
|---|---|
| **前缀匹配** | 写目录前缀即授权整棵子树；写到文件名即只授权那一个文件 |
| **30 分钟自动过期** | 按文件修改时间算。过期后钩子恢复拦截，**忘了删也不会长期敞口** |

⚠️ 放行条**不进 git**（各项目 `.gitignore` 已排除）。它是一次性的临时通行证，不是配置。

### 第三步：改完，提醒用户对方仓库要补日志

改动落在对方仓库里，**对方的 `pre-commit` 硬闸会在提交时拦住它**，要求补 `CHANGE-LOG.md`。
所以改完必须明确告诉用户：

> 我改了 `<对方项目>` 的 `<文件>`。你去那个项目提交时，它的提交闸门会要求你补一条 CHANGE-LOG 记录，
> 建议写：`| <日期> | <改了什么> | 由 <本项目> 跨项目授权修改 |`

**不要替对方项目提交**，也不要跑去替对方改 CHANGE-LOG——那本身又是一次越界。

### 第四步：删掉放行条

```
rm .claude/cross-edit-allow
```

忘了也不致命（30 分钟后自动失效），但养成删的习惯。

## 4. 🔴 已知局限（如实写在这里，不许当它是铁桶）

| 局限 | 说明 |
|---|---|
| **Bash 绕得过去** | 钩子只挂在 `Write` / `Edit` 上。用 Bash 跑 `cat >`、`sed -i`、`cp`、`mv` 写文件，钩子看不见 |
| **只管 agent** | 人手动改文件不经过 Claude Code 的工具层，钩子无从拦截 |
| **只管本项目的钩子** | 在别的项目目录里开会话，走的是那个项目的钩子设置 |
| 🔴 **拦不住「父项目改子项目」** | 子项目物理上就在父项目树**内**（`projects/<子项目>/`），钩子按「是否在树内」判定，所以这个方向**一律放行**——而 §1 的清单里它恰恰是第一条越界。这条纯靠纪律：要改就去那个子项目的目录开会话 |

⚠️ **明知有 Bash 这个口子还去用它绕过拦截，是明知故犯，不是变通。**
这条最终靠**纪律 + 人工审阅 diff** 兜底：拦截器挡的是「忘记」，挡不住「蓄意」。

反过来说，这也是为什么每个项目都要有自己的 `pre-commit` 硬闸——
**越界改动无论怎么进来，最终都要在对方仓库的提交环节被要求留下日志。**
