## 这是什么

一个知识沉淀仓库。同时是**「文档仓库」范式的可复制样板**。

```
inbox/      📥 随手扔进来的原始材料（未整理、未核实）
archive/    ✅ 已整理、已编号、可被引用的知识
README.md   🔴 全部内容的索引表
```

---

## 🔴 文档仓库范式

### 1. 新东西先进 `inbox/`，不直接进 `archive/`

**任何新材料一律先落 `inbox/`。** 聊天记录、会议摘录、灵感便签、别人发来的文档——先扔进去。

理由：整理是有成本的，而**大部分材料在被整理之前根本不知道值不值得整理**。
强行要求"进来就整理好"，结果是**根本不往里放**——材料留在聊天记录里，等于没有。

`inbox/` 文件命名：`YYYY-MM-DD-一句话说明.md`

### 2. 定期归档：整理 → 编号 → 移入 `archive/`

归档不是"移动文件"，是**四件事**：

| # | 动作 |
|---|---|
| 1 | **核实**——把"听说""印象里"这类没根据的话查清楚，或明确标注为未核实 |
| 2 | **结构化**——原始材料是流水账，归档件要有小节、表格、可跳读 |
| 3 | **编号**——`NN-主题.md`，两位数字前缀 |
| 4 | **进索引**——README 索引表加一行。**不加索引等于没归档** |

🔴 **归档不动原始材料的原话。** 需要保留原话的（如口述记录）就整段引用，
**不要润色**——润色会把"他自己也不确定"这类信息抹掉。

### 3. 🔴 每份材料头部必须标：来源 / 日期 / 可信度 / 状态

```markdown
> **来源**：哪来的（会议 / 聊天 / 公开文档 / 自己想的）
> **日期**：YYYY-MM-DD（有多次修订就列出来）
> **可信度**：🟢 高 / 🟡 中 / ⚪ 无 —— **并写清为什么是这一档**
> **状态**：📥 inbox 未归档 / ✅ 已归档
```

可信度分档：

| 档 | 含义 |
|---|---|
| 🟢 高 | 有权威出处，或经当事人确认过 |
| 🟡 中 | 一手信息但未核对，或部分主观判断 |
| ⚪ 无 | 想法、猜测、未验证的推论 |

**同一份文档里不同章节可信度不同时，要分别标**（`archive/02` 就是这么做的：
功能对比来自官方文档，运维成本是主观判断）。

### 4. README 必须索引全部内容

**一份材料一行，不许遗漏。** README 索引表是这个仓库对外（尤其对 AI agent）的唯一接口——
agent 靠它决定读哪个文件，而不是把整棵树读一遍。

`.githooks/pre-commit` 会强制这条：`docs/` 或 `projects/` 下有新增/删除/改名而 README 未同步 → 拒绝提交。
⚠️ **但 `inbox/` 和 `archive/` 不在钩子的强制范围内**（钩子只认 `docs/` 和 `projects/`），
所以这两个目录的索引**靠纪律**。加了文件就去改 README，别等人提醒。

### 5. 🔴 这里只沉淀知识，不做别的

| 不做 | 该去哪 |
|---|---|
| 写代码 | 代码项目 |
| 做决策 | 决策要有人负责，写进那个项目的决策文档 |
| 跑实验 | 实验项目 |
| 存放临时草稿 | 你自己的笔记，别放这 |

理由：文档仓库的价值在于**被引用时可信**。混进未定的决策和实验中间态，
引用的人就得先判断"这条到底算不算数"——那这个仓库就废了。

### 6. 知识变了怎么办：追加变更记录，不改正文

见 `archive/01` §5 的做法。**改正文会让历史消失**，
而读的人往往需要知道"什么时候开始是这样的"。

例外：**发现原先就写错了**，改正文 + 在变更记录里写明"本文档原先记错了"
（`archive/01` §2 第一行就是这种情况）。

## 干活纪律

### 提交

```
git add <显式路径>     # 🔴 不用 -A / .
git commit
```

`.githooks/pre-commit` 强制：改任何东西 → `CHANGE-LOG.md` 必须一起暂存。
🔴 日志必须**真的新增一行记录**——把本次说明改写进上一条记录那一行不算，闸门会拒。

启用钩子（clone 后一次）：`git config core.hooksPath .githooks`

### 边界

只写本项目树内的文件，跨界走 `.claude/rules/boundary.md` §3 的授权流程。

### 保持真实

**不确定的就标不确定。** 这个仓库最大的风险不是内容少，是**内容看起来很确定其实是猜的**。
