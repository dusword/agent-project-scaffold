## 🔴 实验项目范式

### 1. `EXPERIMENTS.md` 只增不改

**写过的轮次一个字都不许回头修改。** 包括写错的假设、判断失误的结论、后来被推翻的数字。

结论变了 → **追加新一轮**，在新一轮里写「本轮推翻了第 N 轮的结论，因为……」。

理由：这份文件的价值不在最终结论（那在 `docs/04-结论与方案.md`），
而在**记录当时是怎么想的、错在哪**。改对了等于把最贵的信息删了。

### 2. 每轮实验四要素，缺一不算一轮

| 要素 | 要求 |
|---|---|
| **假设** | 写成可被证伪的句子。「看看哪个好」不是假设 |
| **做法** | 数据来源 / 参数 / **可复现的命令**。别人照着敲能跑出同样的数 |
| **数字** | 表格。**不许只写「明显更好」**，要有具体数值 |
| **判定** | ✅ 假设成立 / ❌ 假设不成立。**部分成立要拆开写**（本项目第 2 轮就是 ✅+❌） |

再加一段**「导出的新方向」**和一段**「诚实边界」**——后者写清这轮没测什么、
什么条件下结论会失效。

### 3. 🔴 负面结论也是资产

「A 不行」和「B 行」一样值钱，**必须留档**，写进 `docs/04-结论与方案.md` §4。

本项目最有价值的产出恰恰是一条负面结论（N1：「LFU 领先会随容量扩大」是错的），
因为它把「优化缓存策略」从必做降级成了「先看内存够不够」。

**不许因为「结果不好看」就不记。**

### 4. 🔴 花钱前先报预算

调付费接口、大规模跑数、申请云资源**之前**：
先更新 `docs/01-痛点与需求.md` §5 的预算表，**说清要花多少、买什么结论**，等确认再动手。

本项目当前全部在本机用标准库跑，没有花钱环节。

### 5. 脚本只吐数字，判定由人做

`experiments/` 下的脚本**不打印判断、不写文件、不改 `EXPERIMENTS.md`**。
理由见 `docs/02-关键决策.md` D2：让脚本自己判定，等于让被测者给自己打分，
而且会把「假设错了」这种最有价值的记录自动抹平。

### 6. 可复现是硬要求

脚本质量可以是「够用就行」（这不是代码项目，脚本不是交付物），
但**必须可复现**：固定随机种子、样例数据入库、命令写进 `EXPERIMENTS.md` 的「做法」。

判据：**换台机器重跑，数字必须一模一样。**

## 干活纪律

### 提交

```
git add <显式路径>     # 🔴 不用 -A / .
git commit
```

`.githooks/pre-commit` 强制：改任何东西 → `CHANGE-LOG.md` 必须一起暂存；
`docs/` 有新增/删除/改名 → `README.md` 必须一起暂存。
🔴 日志必须**真的新增一行记录**——把本次说明改写进上一条记录那一行不算，闸门会拒。

启用钩子（clone 后一次）：`git config core.hooksPath .githooks`

### 边界

只写本项目树内的文件，跨界走 `.claude/rules/boundary.md` §3 的授权流程。

### 保持真实

数字就是数字，不许美化。假设错了就写 ❌ 并留着。
**「诚实边界」那一段不许省**——省掉它，下一个人会拿着不适用的结论去做决定。
