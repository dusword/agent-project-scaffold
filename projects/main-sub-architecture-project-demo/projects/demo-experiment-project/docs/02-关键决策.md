## D1 · 用合成轨迹起步，不申请生产数据

| 项 | 内容 |
|---|---|
| **决策** | 第一阶段全部用**固定随机种子生成的合成轨迹**（`seed=20260819`），不申请生产数据采样 |
| **依据** | 我们要回答的是「策略选型」这种**结构性问题**——不同策略的相对高下由分布的**形状**决定，不由绝对数值决定。形状对了，结论方向就对；真实数据只影响具体多少个百分点 |
| **否掉的替代** | ① **直接申请生产数据采样**：要走数据审批（预计 1~2 周），而且在还不知道值不值得做的时候占用审批额度不划算；② **在生产上直接灰度试**：运维已经踩过「加缓存反而变慢」的坑，拿生产当实验场不可接受 |
| **好处** | 当天就能出第一轮结果；实验完全可复现（种子固定，任何人重跑数字一致）；不涉及任何真实业务数据，没有合规负担 |

🔴 **代价必须写明**：合成轨迹的分布参数是我们拍的。
如果生产实际分布与假设明显不同，**所有数字都要重跑**。
这条代价在 `EXPERIMENTS.md` 每轮的「诚实边界」里重复登记，不许省略。

## D2 · 脚本只吐数字，判定与结论由人写

| 项 | 内容 |
|---|---|
| **决策** | `experiments/run_cache_bench.py` **只输出测量结果**，不打印任何「A 优于 B」的判断，也不写文件 |
| **依据** | 判定要结合本轮之外的信息（业务约束、实现成本、上一轮的导出方向）。脚本看不到这些，它给出的「结论」必然是片面的。第 2 轮就是活例子：脚本只吐了 8 行命中率，而真正有价值的发现——**LFU 对扫描完全免疫、但领先幅度随容量收窄**——是人把两轮数字并排看才得出的 |
| **否掉的替代** | ① **让脚本自动判定胜者并写进 EXPERIMENTS.md**：等于让被测者给自己打分，而且会把「假设错了」这种最有价值的记录自动抹平成「结论正确」；② **脚本输出结构化 JSON 供后续自动汇总**：现阶段只有 2 轮、8 行数字，引入汇总层是过度工程 |
| **好处** | `EXPERIMENTS.md` 里每一条判定都有人负责；「假设错了」能被如实记下来（第 2 轮的 ❌ 就是这么留下来的） |
